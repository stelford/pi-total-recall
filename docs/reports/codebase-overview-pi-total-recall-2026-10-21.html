Executive Summary

pi-total-recall adds durable, SQLite-backed “fact” memory to the Pi coding agent. It is a tiny two-runtime project: a Python MCP server (facts.py for storage, server.py for the FastMCP tool surface) and a single TypeScript Pi extension that registers that server, auto-captures facts at the end of every agent cycle, and adds /recall and /recall-stats commands. The whole hand-written surface is ~524 lines of source plus ~290 lines of tests across 8 files.

The project is deliberately written as a learning example of two things at once — a Pi extension and a minimal FastMCP tool surface — and every behaviour was built red→green TDD-style from an OpenSpec change (openspec/changes/archive/2026-10-21-add-total-recall-memory/). Both test suites and the typecheck pass at the time of the sweep. It is a personal tool, not a published package: no CI, no license, no packaging, one commit.

Key Points

  • Exactly three MCP tools — store_fact, retrieve_facts, stats — over the stdio transport, registered with exposure: "direct" so the model sees them as mcp__total-recall__<tool>.
  • Clean storage/MCP seam: facts.py imports only sqlite3/os/pathlib and takes a sqlite3.Connection; server.py is a thin wrapper. The store is testable with no FastMCP in the process.
  • Two independent MCP paths: the model calls the registered server, while automatic capture opens its own short-lived McpClient + StdioTransport because agent_end handlers have no executeTool().
  • Capture is LLM-distillation, not string extraction — distillFacts() spends one bounded completion per cycle. This migration is in flight and uncommitted: tests/extract.test.ts deleted, tests/distill.test.ts added, README rewritten.
  • Everything passes right now: 10 pytest + 11 vitest tests green, tsc --noEmit clean.
  • Spec drift: openspec/specs/cycle-capture/spec.md still specifies the old “newest user message” extraction rule the deleted extractFacts implemented.
  • No CI, no lint gate in repo — and a live uvx ruff check . already reports 1 import-order error in tests/test_facts.py.

Architecture

Two processes, one contract. The Python MCP server owns persistence; the TypeScript extension owns the Pi integration. They talk MCP-over-stdio, in both directions of initiative: Pi (and therefore the model) may call the registered server, and the extension separately spins up its own client to write facts from an event handler. The database is plain stdlib sqlite3 with a single facts table and no ORM, no migrations, and no FTS.

Data / control flow

  • Load: Pi discovers the extension via pi.extensions in package.json and calls the default export totalRecall(pi), which registers the MCP server (command: pythonCommand(), args: [server.py], cwd: projectRoot(), env.TOTAL_RECALL_DB, exposure: "direct") plus two commands and one event handler.
  • Model-facing recall: the model calls mcp__total-recall__retrieve_facts / ...stats / ...store_fact; Pi owns that connection.
  • Auto-capture: agent_end → distillFacts(ctx, messages, 3) → one ctx.modelRegistry.complete() with a system prompt asking for a JSON array → parseDistilledFacts() (first [ to last ], so prose/code fences are tolerated) → trim to 200 chars, dedupe, cap at 3 → withClient() spawns python server.py, calls store_fact(fact, source:"auto") per fact, closes.
  • Prompt budget: last 16 messages, 800 chars each, then the whole transcript slice is capped at 8 000 chars — so an injected skill prompt cannot dominate distillation.
  • Commands: /recall <query> → retrieve_facts(query, limit:5); /recall-stats → stats(). Each opens its own short-lived client.
  • Payload normalisation: FastMCP may return a list as {result:[...]}, as data/structuredContent/structured_content, or as JSON in a text block; toolData() tries all four and normalizePayload() collapses them to FactRow[] | {total:number} | undefined.
  • Failure policy: the agent_end handler catches distillation and storage errors separately and only calls ctx.ui.notify(..., "warning") — it never throws into the session. Command handlers notify with "error".

Coding Style & Conventions

  • Python: from __future__ import annotations in both modules; PEP 604 unions (str | Path | None); one-line summary docstrings on every public function; parameterised SQL only; eager conn.commit() after each write; functions accept an injected sqlite3.Connection so tests can pass a temp DB.
  • Error idiom (Python): raise built-ins with a message — ValueError("fact must not be empty"), RuntimeError("failed to store fact"). No custom exception hierarchy. server.py does not catch: FastMCP surfaces it.
  • TypeScript: module-level const knobs for every magic number (DEFAULT_MAX_FACTS, MAX_FACT_LENGTH, RETRIEVAL_LIMIT, DISTILL_MAX_MESSAGES, DISTILL_MAX_CHARS_PER_MESSAGE, DISTILL_MAX_TRANSCRIPT_CHARS); pure helpers (distillPrompt, parseDistilledFacts) split out from I/O and exported for unit tests; narrow unknown-guarding accessors (partText, contentText, errorText) instead of casts on untrusted model output.
  • Defensive by default: optional-chaining everywhere the Pi context is touched (ctx.ui?.notify?.(), if (!ctx.model || !ctx.modelRegistry) return [], event.messages ?? [], projectRoot() falls back to process.cwd()).
  • Local API stub: extensions/pi-types.ts re-declares the subset of the Pi API used, to avoid depending on @earendil-works/pi-coding-agent just to typecheck. The real shapes arrive at runtime.
  • Logging: none in Python; the extension reports only via ctx.ui.notify at info/warning/error. StdioTransport is constructed with stderr: "pipe".
  • Tests: Python per-function tests named test_<behaviour> with a make_conn(tmp_path) helper; TypeScript grouped in describe() blocks with a ctxWith(text) fake registry. Imports use import type for type-only imports (enforced by verbatimModuleSyntax).

Testing

  • Frameworks: pytest (>=8.0) for Python, vitest (^2.1) for TypeScript. pytest is configured in pyproject.toml with testpaths = ["tests"] and pythonpath = ["."]; vitest needs no config file and is invoked as vitest run.
  • Four tiers: pure store unit tests (test_facts.py, 8 tests) → in-memory MCP tests (test_server.py, 2 tests via fastmcp.Client, no subprocess) → pure TS helper tests with a fake ModelRegistry (distill.test.ts, 10 tests) → one cross-language integration test that launches server.py over stdio with the exact client the extension uses (mcp.integration.test.ts, 1 test, 30 s timeout).
  • No Pi process needed: tests never start Pi. The integration test reads TOTAL_RECALL_PYTHON or .venv/bin/python and is wrapped in describe.skipIf(!existsSync(python)) so a fresh checkout still passes.
  • Isolation: every test points TOTAL_RECALL_DB at a tmp_path/mkdtemp database; the real ~/.pi/total-recall/facts.db is never touched.
  • Single test: uv run pytest tests/test_facts.py::test_stats_counts_facts or npx vitest run tests/distill.test.ts -t "deduplicates". [inferred from pytest/vitest conventions — not run during this sweep.]
  • Coverage gap: no test exercises totalRecall() itself, i.e. registerMcpServer, the agent_end wiring, the /recall commands, or the toolData()/formatFacts() payload normalisation.

  • No containerisation or IaC: no Dockerfile, compose file, Helm chart, or Terraform.
  • Deployment model is “install into your own Pi”: the package is consumed in place from the working tree via pi install <absolute path> or pi -e <path>. Confirmed live: ~/.pi/agent/settings.json already lists ../../work_folder_local/pi/pi-total-recall, so this checkout is the deployed artifact.
  • Critical caveat from the README: Pi loads local packages in place and does not run npm install for them, so node_modules/@earendil-works/pi-mcp must exist in this exact directory for the extension to load.
  • Environments: one — the developer machine. No staging, no secrets store, no observability stack. The only “service” is a per-invocation stdio subprocess.
  • VCS hygiene: git is the underlying store but jj drives it (.jj/ present; jj log shows one described commit plus an undescribed working-copy change). Any automation must assume jj-first workflows. No AGENTS.md to say so.

Data & External Services

  • SQLite, one table, no migrations. facts(id INTEGER PRIMARY KEY AUTOINCREMENT, fact TEXT NOT NULL, tags TEXT DEFAULT '', source TEXT DEFAULT '', created_at TEXT DEFAULT (datetime('now'))), created by init_db() via CREATE TABLE IF NOT EXISTS. Schema changes would need a hand-written migration story that does not exist.
  • Default database: ~/.pi/total-recall/facts.db (outside the repo; *.db and *.db-journal are gitignored). Present on this machine (12 KB) but queried read-only at 0 rows — the table exists, no facts have been captured yet. [inferred] the distillation path has not yet produced a stored fact in a real session.
  • Retrieval is substring LIKE, not semantic: WHERE fact LIKE ? OR tags LIKE ? with %query%, ORDER BY id DESC LIMIT ?. Two consequences: no index (fine at this size), and SQLite's built-in LIKE only case-folds ASCII, so non-ASCII queries are effectively case-sensitive.
  • External service: the session LLM. distillFacts needs ctx.model and ctx.modelRegistry.complete; without valid credentials auto-capture silently yields []. The manual store_fact tool still works.
  • External service: the Python interpreter as a subprocess. pythonCommand() defaults to <projectRoot>/.venv/bin/python; if uv sync has not been run, every command and every agent_end capture fails.
  • No queues, caches, feature flags, or third-party APIs beyond the model provider.

Risks & Notable Issues

  • High Spec drift after the distillation rewrite. openspec/specs/cycle-capture/spec.md still says extraction SHALL “derive facts from the most recent user message”, and the archived tasks.md 4.1–4.2 still reference extractFacts / tests/extract.test.ts — but the code now distils via the model and that test file is deleted while tests/distill.test.ts is still untracked. Anyone coding to the spec will build the wrong thing. The rewrite is also sitting uncommitted (jj change rpmsuwyl, no description).
  • High One model completion per agent cycle, unconditionally. Cost and latency on every run, no opt-out flag, no debounce, and no dedupe against facts already in the store — the same fact is re-stored every session. Combined with no retention/eviction policy this is unbounded growth by design.
  • Medium Subprocess per operation. withClient() spawns python server.py per /recall, per /recall-stats, and once per agent_end; the observed integration round-trip cost ~924 ms, dominated by FastMCP interpreter startup. The README acknowledges this.
  • Medium Unvalidated limit. retrieve_facts passes limit straight into LIMIT ?; a negative value is accepted by SQLite (unbounded, [inferred]) and a huge one is unbounded cost. No cap in facts.py; only the extension's RETRIEVAL_LIMIT = 5 guards the UI path — the model can pass anything.
  • Medium Zero test coverage on the integration seam that matters most: totalRecall(), the agent_end handler, the two commands, and the four-shape toolData() normalisation are untested. The normalisation logic is in fact duplicated verbatim between extensions/total-recall.ts and tests/mcp.integration.test.ts, so the test validates its own copy rather than production code.
  • Medium Type-only stub can silently drift from real Pi. extensions/pi-types.ts hand-declares ExtensionAPI, ExtensionContext and ModelRegistryLike. Pi 1.3.0 is the target, but nothing verifies these shapes; a rename upstream typechecks fine and fails at runtime. Note the real pi-types.ts is already among the modified-uncommitted files (+27 lines for the distillation surface).
  • Low Lint is not a gate. uvx ruff check . reports I001 (unsorted imports) in tests/test_facts.py; there is no ruff config, no ruff/prettier script, and no CI to catch it.
  • Low Cache/artifact hygiene gaps: __pycache__/ (bytecode for server and facts) at the repo root, plus .pytest_cache/, .ruff_cache/ and node_modules/ are all on disk. The .gitignore covers them, but the root-level __pycache__ shows tests have been run without pythonpath isolation.
  • Low No license, no security story, no single-writer guarantee. private: true with no LICENSE file. Each call opens its own sqlite3 connection with no WAL or busy timeout, so concurrent Pi sessions sharing ~/.pi/total-recall/facts.db could hit database is locked. Facts are also stored and recalled in plaintext.
  • Low Injected-prompt surface. Session transcripts are sent to the model to be summarised into “durable facts”, then persisted and replayed into future sessions via direct-exposure tools — a memory-poisoning vector with no review step. The README flags judgment quality but not this.

Recommended Next Steps

  • Finish the extraction→distillation rewrite cleanly: commit the 5 in-flight paths in jj with a description, and open a follow-up OpenSpec change that amends openspec/specs/cycle-capture/spec.md (replace the “most recent user message” requirement with the distillation contract, prompt budget, parse-tolerance and dedupe rules) and the archived tasks.md references.
  • Add the cheapest CI that matters: one workflow running uv sync → uv run pytest -q → npm ci → npm test → npm run typecheck, plus ruff check and ruff format --check. Fix the existing I001 in tests/test_facts.py as part of it, and commit a [tool.ruff] block so lint is reproducible.
  • Share the normalisation code: export toolData()/normalizePayload() from the extension and import it in tests/mcp.integration.test.ts instead of keeping a second copy; then add unit tests for the four payload shapes plus the undefined fallback.
  • Bound the write path: validate limit in facts.retrieve_facts() (clamp to 1..N), skip duplicate facts before storing (exact-match lookup, or checksum column), and decide a retention policy (max rows, TTL, or a prune tool). Wire the distillation budget (16/800/8000/3) to environment overrides.
  • Harden SQLite for concurrent sessions: enable WAL and set a busy_timeout in connect(), or hold one long-lived client instead of spawning a subprocess per call.
  • Make the Pi contract verifiable: either depend on @earendil-works/pi-coding-agent types in devDependencies and delete extensions/pi-types.ts, or add a smoke test that asserts the shapes the extension relies on against a real Pi 1.3.0 install.
  • Decide the publishing story: add a LICENSE (or an explicit “personal tool, no distribution” note), an AGENTS.md recording “jj-first” workflow and the two test commands, and a note in the README that npm install must be re-run after moving the checkout because of the hard-coded paths in .pi-lens.json and pyrightconfig.json.
